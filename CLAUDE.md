# Claude.md — BojuBot
## What
Obsidian plugin. Core feature: Claude Code CLI as subprocess (NOT API, NOT Agent SDK). No API key for AI — rides Pro/Max sub. Desktop only.

BojuBot is not limited to features that involve Claude Code directly. Obsidian-native features (voice input/output, live transcription, canvas, template integration, etc.) are in scope when they enhance the note-taking + AI workflow. New non-Claude features should still fit the "AI-enhanced Obsidian" mission — don't add things just because they're possible.

## Architecture (locked — don't revisit without discussion)
- `child_process.spawn` → `powershell.exe -NonInteractive -Command "& 'claude.exe' ..."` (Windows/Electron stdout fix)
- **Prompt is written to `proc.stdin`, NOT passed as a CLI arg.** `proc.stdin.write(prompt)` then `proc.stdin.end()`. This avoids all Windows shell-quoting issues (smart quotes, double quotes, special chars).
- `proc.stdin.end()` closes stdin so claude doesn't hang waiting for more input
- Flags: `--output-format stream-json --verbose --print` + permission-mode args (see below)
- Permission modes map to CLI args via `permissionArgs()` in `src/backends/claudeCode.ts`:
  - **All modes**: `--permission-prompts none` appended when the CLI lists `--permission-prompts` — anything that would prompt is denied explicitly and lands in `permission_denials` (drives the denial card). Harmless under bypassPermissions.
  - **Standard** (default): `--permission-mode acceptEdits`. Bash denial is explicit via `--permission-prompts none` (#291) on CLIs that support it, emergent from `--print` mode on older ones. The CLI auto-approves read-only Bash commands it classifies as safe (`echo`, `ls`) in acceptEdits; anything else (e.g. `curl -o`) is denied. Do NOT use `--disallowedTools Bash` — it removes Bash entirely, so nothing is denied and the denial card never appears.
  - **Read-only**: `--permission-mode manual --allowedTools Read,Glob,Grep,WebFetch,WebSearch` (`default` instead of `manual` when the CLI doesn't list `manual` — #352)
  - **Full**: `--permission-mode bypassPermissions`
  - **Restricted** (planned #154): `--permission-mode manual|default --allowedTools Write,WebFetch,WebSearch` + vault tree injection suppressed
- **Session-owned state** (#405): the permission mode belongs to the session. It lives in the coordinator's `SessionState` (`_s.permissionMode`) and every session saves it in `StoredSession.permissionMode` (new sessions: the mode they start in; sessions with none open as Standard — Chat only when the conversation can't continue in Standard, i.e. an Antigravity `bojubot-chat` conversation — and that's saved). `settings.permissionMode` is only the default for new sessions — never read for an open session. A picker sets the default and calls `plugin.notifyPermissionPicked(mode, view)`: only that panel (the toolbar's own tab; the target panel for Ctrl+P) gets `onPermissionModePicked()` → `setSessionPermissionMode()` (saved, via `updateStoredSession()`), every other tab just refreshes its icon (`onDefaultPermissionModeChanged()`); the settings-tab dropdown sets the default only (`notifyDefaultPermissionChanged()`); the denial card and request-permission card call `setSessionPermissionMode(mode, sessionFileIdTheCardWasShownIn)`, which refuses when that session isn't open. No in-memory permission override exists. Full access with `persistFullAccess` off: a session saved in Full reopens in Standard unless it was put in Full in this run (`plugin.keepsFullAccess()` / `noteFullAccess()`, a per-session in-memory set). Opening, starting or clearing a session drops the queued system note (coordinator), input-area attachments including pinned ones, unsent Custom Session setup and a pending mode change (`ClaudeView.dropPendingSessionState()`, per tab).
- **CLI capability detection**: after `findClaudeBinary()` the plugin runs `claude --version` then `claude --help` (async, 10 s timeout each, same PowerShell spawn pattern via `runClaude()`), parsed by `parseCliCapabilities()` in `src/utils/cliCapabilities.ts` into `plugin.cliCapabilities` (in memory, not cached). Spawn args are built from it (`spawnClaude({ capabilities })` → `permissionArgs(mode, caps)`). Unknown capabilities (probe pending or failed) must always produce the long-standing args byte-for-byte. Never send a flag or value the CLI didn't list.
- **Effort**: `--effort <level>` after `--model`, only when the CLI lists `--effort` and the level is in `caps.effortLevels` (enforced in `buildSpawnArgs()` / `buildAgySpawnArgs()`). Model and level are resolved together by `resolveTurnModel()` in `src/utils/agentModels.ts` (`SessionCoordinator.getTurnModel()`; `getEffectiveModel()` / `getEffectiveEffort()` / `getEffortLevels()` read it): session pin (`StoredSession.effort`, Custom Session), then the level an old effort-variant model ID implied, then the **agent's own default** (`plugin.getDefaultEffort(id)`: `settings.defaultEffort` for Claude Code, `settings.agyDefaultEffort` for Antigravity; `''` = Default = flag omitted). The effort picker sets the session agent's default only. Re-applied on every spawn including `--resume`.
- **Antigravity effort variants** (#402): `agy models` lists each model once per level (`gemini-3.8-flash-low/-medium/-high`, "Gemini 3.8 Flash (Low)"). `listAgyModels()` collapses them with `collapseEffortVariants()` into one base model with `ModelOption.effortLevels` (GPT-OSS 120B: medium only); `backend.effortVariants` marks the backend. A turn sends the base model + `--effort` (`agy --model gemini-3.8-flash --effort low`); a variant ID with `--effort` is rejected ("conflicts with --effort"), so `resolveTurnModel()` never pairs them and `buildAgySpawnArgs()` strips the suffix whenever it sends a level. A level the model lacks falls back to its nearest (`nearestLevel()`, lower on a tie) — so a Claude default can't produce an invalid agy level. Old saved variant IDs keep working: `loadSettings()` migrates `agyDefaultModel` to base + `agyDefaultEffort`, `loadSession()` turns a variant model pin into base + effort pin (`migrateVariantModel()`), and with no sendable level the variant ID itself is sent.
- **Agent + model picker** (#402): `AgentModelPickerModal` (`src/modals/AgentModelPickerModal.ts`), one section per backend from `BACKEND_IDS` headed by `backend.label` (not installed → greyed, "not installed"). Opened by the model indicator, `/model`, "Switch model" and Custom Session's "Agent and model" field. `ClaudeView.onModelPicked()`: the pick sets `settings.backend` and that agent's default model, then `modelPickAction()` decides — same agent → mid-session model switch; other agent with no conversation (and no first turn running) → `coordinator.switchBackend(id, mode)` (drops the old agent's model/effort pins, works on Custom Session-pinned sessions too); other agent with a conversation → new session on it in the same tab (new tab while a reply runs, #399) with a notice. The session's permission mode carries over through `modeForAgentSwitch()`: same mode, else the nearest with less access, never more; `null` (Chat only on an agy without its agent definitions) refuses the switch with a notice. Indicator: agent icon + `agentModelIndicatorText()` ("Claude · Claude Sonnet 5.5 · high"); `updateModelIndicator()` also refreshes the welcome header's "agent · model".
- **Live streaming**: `--include-partial-messages` when the CLI lists it and `settings.streamPartialMessages` (default on). `stream_event` text deltas feed `onTextPreview(blockText)` (main thread only — events with `parent_tool_use_id` are ignored); the buffer resets on `content_block_start` and clears when the complete `assistant` message arrives. Previews are **display only**: complete `assistant` messages remain the sole source for text, @@BOJU actions/queries, tool calls, usage and API errors. `turn:text` emits `(display, committed)` where display = committed + `previewForDisplay()` (drops @@BOJU lines and holds back a trailing partial that could become one — `src/utils/streamPreview.ts`); ClaudeView writes display once per `requestAnimationFrame` and renders markdown from committed only.
- `--verbose` required with `stream-json` + `--print` or claude errors
- Delete `CLAUDECODE` from spawn env or claude refuses nested launch
- `--resume <sessionId>` on every turn after first; uses cache_read_input_tokens (~10x cheaper)
- Do NOT prepend history manually — that costs MORE than --resume
- **Chat tabs** (#399): several `ClaudeView` panels can be open at once (Obsidian tabs/splits), one session each, each with its own `SessionCoordinator`. Never `getLeavesOfType(VIEW_TYPE_CLAUDE)[0]`: commands go to the **target panel** = the chat leaf used most recently (`plugin.markChatActive()` on `active-leaf-change` and on focus inside the view; ties/never-used → first leaf; none → open one) via `plugin.withTargetChatView()` / `targetChatView()`; settings/allowlist/capability/default-model changes fan out to every loaded view (`plugin.chatViews()`); a permission pick goes only to the panel it was made in (see Session-owned state), the other views just refresh their icon. A session is never open in two panels: `plugin.openSession()` reveals the leaf that has it (`leafForSession()`, which reads unloaded background tabs' saved view state), else loads into the preferred panel only when `isReusable()` (untouched new session, idle, empty input), else `openChatTab({ sessionFileId })`. `newSession()` opens a new tab when the target is busy (a running reply keeps running instead of #398's Stop prompt; the prompt now only guards Clear session) or on Ctrl/Cmd-click / `new-chat-tab`. Each view persists `{ sessionFileId }` through `getState()`/`setState()` (the first session is chosen in `setState`, with a timer fallback; `{ blank: true }` = choose nothing) and retitles its tab with the session name (`getDisplayText()` + private `leaf.updateHeader()`). Closing a busy tab cancels its turn.
- **Live status** (#399): each `ClaudeView` keeps a `StatusState` (`src/utils/sessionStatus.ts`) fed by `applyStatus()`: `turn:start` → running; `turn:done`/`turn:error` → turn-end (finished/error only when the panel isn't on screen, `plugin.isChatVisible()`; a vault-inject follow-up skips it; a permission request → wait-start first); permission request / UI Bridge command confirmation (`UIBridgeOptions.onAwaitUser`) → wait-start/wait-end; denial card with buttons → denial-shown until upgrade/dismiss/next turn; `active-leaf-change`, `layout-change` and `onResize` → viewed; session switch → reset. A display change sets `data-bojubot-status` on the tab header (private `leaf.tabHeaderEl`, CSS dot), updates the Sessions panel dots in place (`SessionsView.updateStatuses()`), and shows a clickable Notice (`statusNotice()`) when the panel isn't visible.
- **Chat only = no vault information from BojuBot either** (#406): gates in `src/utils/modeGates.ts`, always fed the session's effective mode. Chat only refuses vault queries except `help`, skips the open-note/split/stacked hint, and picking it for a session with messages whose saved mode isn't Chat only starts a new session saved in Chat only (`needsFreshSessionForChatOnly`, one rule of `SessionCoordinator.modeNeedsNewSession()` — the single "this mode change needs a new session" check, which also covers Antigravity leaving Chat only, #403 — then `ClaudeView.startSessionForModeChange()`; deferred to the next send while a turn runs). Chat only and Read only refuse `run-command`, and their orientation (`{{IF_...}}` line tags in `src/orientation.md`) and allowlist notes leave commands out. New BojuBot-to-agent channels must go through these gates.
- Vault root = cwd for all spawns by default; per-session `cwd` override stored in session JSON and used on every spawn including `--resume`
- Sessions: `.obsidian/bojubot/sessions/<id>.json` (metadata only; actual history in `~/.claude/projects/`); schema includes optional `cwd` field and optional `backend` (absent = Claude Code; a session stays bound to its backend, `claudeSessionId` holds the conversation ID for every backend)
- **Antigravity agents** (#403): agy fixes a conversation's agent (tool list + system prompt) when the conversation starts; `--agent` on a resumed turn is ignored, so it's sent on the first turn only. `src/backends/agyAgents.ts` generates two definitions: `bojubot` (Standard, Read only, Full; every tool agy's agent registry accepts — 26 on 1.4.4, incl. `run_command` and the write tools; mode-neutral ruleset: vault-relative wikilinks, never file:// or backticked links, file tools over shell, rename/move/delete via UI Bridge, `request-permission` after a denied shell command) and `bojubot-chat` (Chat only; `search_web` + `read_url_content`, `commandExecutionPolicy: "off"`). Per-turn args stay today's `agyPermissionArgs()` mode flags for `bojubot` and no-agent conversations, so mode switches and the denial-card upgrade work as before; `bojubot-chat` turns run `--dangerously-skip-permissions` (the tool list is the enforcement). A conversation started in Full access has no agent (definitions can't name browser/MCP/`command_status` tools; an unknown name makes agy refuse to start). The agent is picked in `SessionCoordinator.send()` via `backend.conversationAgent(mode, caps)` and stored on the session (`StoredSession.agent`); `modeNeedsNewSession()` (`backend.needsNewConversation`) is true when moving into or out of Chat only on a started conversation — `ClaudeView.onPermissionModePicked()` leaves the session in its own mode and `startSessionForModeChange(mode)` starts a new session saved in the picked mode in the same tab, with a `modeChangeNotice()` (`src/backends/modes.ts`) notice (when idle; while a reply runs the mode is held in `pendingNewSessionMode` and the next send makes the switch), and the denial/permission-request cards don't offer an upgrade the conversation can't take. The probe (`probeAgyCapabilities` → `withAgyAgentDefinitions`) writes `~/.gemini/config/agents/bojubot*.md` only when `agy --help` lists `--agent`, rewrites only changed files, touches nothing else, and sets `caps.agentDefinitions`; `agyAgentsAvailable(caps)` gates agents and Chat only. Fallback (no `--agent`, write failure, or `isAgyAgentRejection()` at runtime → `agy_agent_rejected` card, sticky until plugin reload, rejected first turn binds no conversation): no agent, today's args byte-for-byte, Chat only unavailable.
- **Backends** (agent-backends spec): `settings.backend` picks the CLI for new sessions (no settings-tab control: the model picker sets it, and the setup panel's "Use <agent> instead" button via `renderUseOtherAgent()` when the default agent's CLI isn't found); the plugin keeps binary path, capabilities and model list per backend (`getBinaryPath(id)`, `getCapabilities(id)`, `getModels(id)`, `getDefaultModel(id)`); `SessionCoordinator` resolves everything through its session's `backendId`. `backend.unavailableModes(caps)` / `backend.modeDescriptions(caps)` depend on the CLI's capabilities. Compact and the gauge are hidden on Antigravity (`compactPrompt: null`). History: backends with `readableHistory: false` (Antigravity) get a BojuBot transcript, `sessions/<id>.transcript.jsonl`, appended by `SessionCoordinator` when each turn ends (user text cleaned like Claude history, reply with its @@BOJU lines). Read history only through `hasReadableHistory(session, sessionsDir)` / `loadHistory(session, sessionsDir)`, never `loadSessionMessages()` directly.
- **Agent names in the UI** (three forms, never string-munged): `backend.label` for labels, pickers, settings and section headers ("Claude (Claude Code)", "Gemini (Antigravity CLI)"); `backend.name` in sentences about the conversation or agent ("Chat only needs a new Gemini session"); `backend.cliPhrase` in sentences about installing, signing in, the binary or versions ("Claude Code", "the Antigravity CLI"; `sentenceStart()` capitalizes it), `backend.cliName` for version lines ("Antigravity CLI 1.4.2"). Text that means whichever agent runs says "the agent". Internal IDs (`claude-code`, `antigravity`) never change.

## Architectural direction: two-way bridge (#62)
The vault query protocol (@@BOJU query key, #58) is the first half of the two-way bridge — Claude can now query live vault state (backlinks, outlinks, tags, file-list) on demand. The second half (#62) is a watch/event system: Obsidian pushing vault state changes to Claude proactively. Design #62 as an extension of the existing query infrastructure.

## Code review / bug fix workflow
Before implementing any fix — especially from a code review:
1. Read the finding and explain the current behavior back in plain language.
2. Flag anything where the diagnosis seems incomplete or where context might change the fix. Code reviews are a starting point for discussion, not a prescription.
3. Propose the fix approach and confirm before writing code.
4. Security and correctness bugs get individual PRs. Maintenance items can batch.
5. Larger refactors get a design discussion first — no diving straight into a 2,800-line file split.

## Windows gotchas
- Claude Code must be installed AND logged in natively in PowerShell. `winget install Anthropic.ClaudeCode` + `claude login`.
- Spawn via `powershell.exe -NonInteractive` — cmd.exe (shell:true) and direct spawn (shell:false) both silently swallow stdout in Electron.
- `proc.stdin.end()` is required after spawn.
- **Testing CLI behavior directly** (cheap, no Obsidian): from a scratch dir in `$env:TEMP`, pipe a prompt into `claude --print --output-format json --model claude-haiku-4-5 --setting-sources ""` (`--setting-sources ""` excludes your own allow-rules so results reflect the CLI's defaults). Clear the nested-session guard with `$env:CLAUDECODE = $null` (a `Remove-Item Env:` line gets blocked by the tool guard). Slash commands like `/usage` or `/context` piped as the whole prompt run locally at $0. Interactive-only features (`--remote-control`) can't be tested this way — they need a TTY.

## Commits
`feat:` / `fix:` / `docs:` / `chore:` / `refactor:` / `test:`. Breaking: `feat!:` or `BREAKING CHANGE:` footer. release-please handles CHANGELOG + version bumps.

**Lint and TypeScript violations are `fix:` not `chore:`** — they block Obsidian community plugin acceptance and must appear in a release.

**`feat:` is for genuinely new user-facing capabilities only.** Bug fixes (even GitHub-tracked bugs), privacy/consent fixes, default value changes, internal improvements, and enabling behavior that was always designed but not yet on by default all use `fix:`, `chore:`, or `refactor:`. Mislabeling fixes as features inflates minor version numbers unnecessarily — release-please uses commit types directly to determine version bumps.

After submitting a PR, always switch back to `main`: `git checkout main && git pull`.
When Scott says a branch is merged or deleted, immediately run `git checkout main && git pull`, then create a new branch before continuing any work.

## Beta builds
Testers install betas with BRAT (user guide: `docs/guide/beta-builds.md`). `.github/workflows/beta-release.yml` builds the plugin and publishes a GitHub **pre-release** with `main.js`, `manifest.json` and `styles.css`.
- **Automatic:** `release.yml` calls it on every push to `main` that changes the plugin. It skips release commits and pushes that only touch `docs/`, `notes/`, `.github/` or top-level `.md` files.
- **Manual:** Actions → Beta Release → Run workflow, on any branch (e.g. a `dev` integration branch). Leave the version blank for the next automatic number, or enter one such as `3.9.0-dev.1`.
- **Version:** the open release-please PR's version plus `-beta.N` (e.g. `3.8.0-beta.3`); with no release PR open, the next patch. Only the uploaded `manifest.json` carries it. Never commit a beta version to `manifest.json` on `main`: the Obsidian marketplace reads that file.
- **Pruning:** only the newest 5 `-beta.N` pre-releases are kept; older ones and their tags are deleted. Hand-named betas (not `-beta.N`) are never pruned.
- **Docs for unreleased features:** docs deploy from `main`, so they run ahead of the marketplace. Mark pages or sections for features that are only in betas with `<Badge type="warning" text="Beta" />` after the heading, and a `::: warning Not released yet` container that links to the beta builds page (see `docs/guide/agents.md`).

## Release notes
**Before merging the release-please PR:** remove the beta badges and "Not released yet" notices for features shipping in that release (`grep -rn 'text="Beta"\|Not released yet' docs/`), in a `docs:` commit.

The docs deployment generates release notes on its own — don't expand `notes/CHANGELOG.md` or edit GitHub release pages unless asked. Setup steps, limitations and how-tos belong in the user docs (`docs/guide/`), never the changelog.
